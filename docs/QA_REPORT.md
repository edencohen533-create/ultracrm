# דוח QA – איחוד UltraCRM (CRM + חייגן + WhatsApp)

תאריך: 24.9.2026 · ענף: `feat/unified-crm` · סביבה: מסד PostgreSQL חדש ומבודד (`ultracrm`), טלפוניה בהדמיה (`TELEPHONY_PROVIDER=mock`), WhatsApp עם ספק mock. **לא בוצעה שום פנייה לספק חי, ללקוח אמיתי או לנתוני ייצור.**

מקורות שנבדקו: `dialer@14922332` (superset של `main@3780347e`), `solinainbox@03e0b261` (`main`). שני מאגרי המקור לא שונו.

## מסקנה

**שילוב מלא ברמת הנתונים והתהליכים, מאומת בסימולציה; האינטגרציה מול הספקים החיים (Telnyx, Meta) עדיין חסומה עד שיוגדרו חשבונות בדיקה.**

הוכחת התהליך החוצה מודולים (איש קשר אחד, `contactId` אחד לאורך כל הדרך): נוצר איש קשר ב-CRM → ליד (שיוך אוטומטי + משימת פנייה ראשונית ע"י worker האירועים) → חיוג מהכרטיס (שיחה משויכת ל-`contactId`, `businessId`, נציג) → ניווט לתיבה ובחזרה בזמן השיחה (פס השיחה נשאר, sink אודיו אחד) → ניתוק, תוצאה והערה → משימת מעקב אוטומטית → שליחת WhatsApp מהכרטיס לאותו `contactId` → תשובה נכנסת (דרך מסלול ה-webhook האמיתי של הספק המדומה) → ההודעות בתיבה ובציר הפעילות של הכרטיס → "הסר" נכנס → חסימה גלובלית בכרטיס, בתיבה ובשליחה → שינוי סטטוס ליד → התנתקות והתחברות מחדש → הנתונים בשרת. ראיות: `docs/qa/browser-results.json`, `docs/qa/shots/*.png`, טבלת ה-API למטה.

## הבחנה בין סוגי הבדיקה

- **קוד/יחידה**: 29 בדיקות ללא DB (נרמול טלפון, CSV, קהלים, קמפיינים, מדיה, סנכרון תבניות, קומפוזר).
- **סימולציה עם DB אמיתי**: 19 בדיקות אינטגרציה + smoke API + 17 צעדי דפדפן – טלפוניה ב-mock adapter (מכונת המצבים והאירועים הם הקוד האמיתי), WhatsApp ב-mock provider (מסלול ה-webhook/הסטטוסים הוא הקוד האמיתי, ללא Graph API).
- **ספק חי**: לא בוצע. חסמים: חשבון Telnyx (Call Control App + Credential Connection + מספר E.164) וחשבון Meta (Token, Phone Number ID, App Secret, תבניות מאושרות), רישום Webhooks לכתובות החדשות, החלפת סיסמאות הדמו.

## הערות ביצועים (סביבת הבדיקה)

מסד Neon באירופה מהמחשב המקומי: ~200ms לכל שאילתה; בקשות מרובות-שאילתות (שליחת הודעה ≈ 25 שאילתות) לוקחות 5–10 שניות במקומי. זו מגבלת סביבה, לא לוגיקה; בפריסה באותו region החביון יורד לכמה מילישניות. בדיקות הדפדפן אומתו מול "אמת השרת" (API) כדי לא להיות תלויות בזמני רינדור.

## יכולות שאבדו / נותקו ביחס למקור

- `dialer`: עבודה לא-מקומטת של ניהול מספרים (רכישה, מוניטין, מדיניות מספרים) לא נכללה – לא הייתה ב-commit שנבחר. Telnyx נשאר ברמת הפריסה (לא לכל עסק).
- `solinainbox`: מסכי המשתמשים/צוותים והתחברות NextAuth הוחלפו בתשתית המאוחדת (בכוונה). Supabase Realtime הוסר (במקור כבר הוחלף ב-polling). כל השאר הועבר.
